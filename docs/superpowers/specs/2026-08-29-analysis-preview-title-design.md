# 内容梳理预览标题优化设计

## 背景

文稿抽屉的“内容梳理”预览会同时显示系统生成的大标题（单集标题后带“｜内容梳理”）和模型正文中的同名一级标题，造成“内容梳理”重复。当前 Markdown 预览的一级标题字号也偏大，挤占了正文的可读空间。

## 目标与范围

- 统一调整“文稿”阅读预览和“内容梳理”预览的主标题为较紧凑的字号，仍保留清晰的层级。
- 当模型正文开头出现独立的 `# 内容梳理` 时，在预览中去掉这一重复标题。
- 不修改已保存的分析 Markdown、frontmatter、复制/下载结果；“学习 Prompt”也使用相同的紧凑标题字号，但不启用重复标题过滤。

## 方案比较

1. **预览层处理（采用）**：将紧凑字号放到所有 Markdown 预览共用的一级标题样式，并仅在内容梳理预览中删除开头的重复一级标题。改动范围小，现有数据可完整保留，旧分析结果无需重新生成。
2. **保存时清洗正文**：生成分析 Markdown 时直接删除重复标题。下载结果会同步变更，但会改变已生成文件，且需要处理更多模型输出变体。
3. **全局缩小一级标题并修改标题生成器**：实现简单，但会影响文稿页，并让分析文件失去统一的结果类型标题，不采用。

## 交互与数据流

分析 Markdown 读取后仍按现有 frontmatter 去除流程处理；所有 Markdown 预览使用统一的紧凑一级标题样式，当前页为“内容梳理”时额外使用 `analysis` 变体：

1. 将正文按行切分。
2. 跳过开头空行；若首个有效行严格匹配 `# 内容梳理`，移除该行及其紧邻的多余空行。
3. 使用共用紧凑 CSS 规则渲染一级标题；`analysis` 变体只负责重复标题过滤。

若正文没有该标题、标题带有其它文字，或该标题不是开头的一级标题，则不做删除，避免误伤正文。

## 测试与验收

- 渲染代码测试确认只有内容梳理预览启用重复标题过滤变体，文稿与学习 Prompt 不启用。
- 样式测试确认文稿、内容梳理和学习 Prompt 预览共享更小的一级标题字号规则。
- 文本处理测试覆盖：开头重复标题被移除、非开头标题保留、其它分析类型不受影响。
- 运行完整 `npm test`、`npm run lint`、`npx tsc --noEmit` 与 `git diff --check`。
