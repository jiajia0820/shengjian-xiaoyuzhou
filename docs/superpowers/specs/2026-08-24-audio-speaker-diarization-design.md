# 本地音频说话人分段设计

- 日期：2026-08-24
- 分支：`feature/audio-speaker-diarization`
- 状态：已实现，待真实音频验收
- 基线：`origin/main`（保留小宇宙登录和自定义 API；不包含此前的意群整理实验）

## 1. 目标与明确不做的事情

本阶段只解决一个问题：用户选择本地音频后，识别音频中的匿名说话人，并把现有小宇宙官方文字稿按说话人轮次分段展示。

明确不做：

- 不调用自定义 API，不做 AI 语义判断；
- 不做“意群”或话题分段，不按字符数、标点或停顿重新切段；
- 不让语音模型重写、纠错、翻译或重新生成正文；
- 不从文字稿猜测“主持人”“嘉宾”等真实身份；
- 不上传音频到 Cloudflare Worker、第三方推理服务或其他远程接口。

音频处理失败时，原始文稿和当前文稿均保持不变。

## 2. 技术选型与理由

首版使用独立 Python 本地服务和 `pyannote.audio` 的开源 `community-1` 说话人分离 pipeline：

1. 浏览器只负责选择音频、显示进度和提交确认；
2. 本地服务只在 `127.0.0.1` 监听，执行音频解码和 diarization；
3. Worker 继续负责账号、单集和文稿的鉴权与保存；
4. 服务返回匿名说话人时间区间，网页按时间区间回填已有 `transcript.json`。

选择 pyannote 的原因是它可以直接输出 `start/stop/speaker` 区间，职责正好是“分辨谁在说话”，不会迫使本项目重复做 ASR。官方代码仓库为 MIT；`community-1` 模型的使用条件和 Hugging Face token 仍需用户在首次安装时接受并配置，模型缓存后音频推理不联网。

备选实现保留在接口之后：

- FunASR + CAM++：中文和 CPU 体验更友好，也能提供 ASR/VAD/说话人流水线；但会重复转写，且工具包许可与模型许可需要分别审核；
- 3D-Speaker：适合未来做声纹注册和跨单集识别，但当前官方示例偏 Linux，首版 Windows 集成成本更高；
- WhisperX：词级时间戳成熟，但同样会重复转写且对本机显存要求更高。

参考资料（官方来源，核查日期 2026-08-24）：

- [pyannote.audio](https://github.com/pyannote/pyannote-audio)（MIT，代码仓库）；
- [pyannote speaker-diarization-community-1](https://huggingface.co/pyannote/speaker-diarization-community-1)（模型使用条件以模型页为准）；
- [FunASR](https://github.com/modelscope/FunASR)（MIT，模型许可另行审核）；
- [3D-Speaker](https://github.com/modelscope/3D-Speaker)（Apache-2.0）；
- [WhisperX](https://github.com/m-bain/whisperX)（BSD-2-Clause）。

## 3. 用户流程

文稿抽屉新增“从本地音频识别说话人”入口：

1. 用户打开已有单集，选择本地音频文件；
2. 页面先检查扩展名、文件大小和音频时长；
3. 通过本地服务 `/health` 检查服务和模型是否就绪；
4. 页面创建本地任务并显示“解码 / 说话人分析 / 对齐”进度；
5. 服务返回匿名说话人区间，网页将区间提交给应用的预览接口；应用读取官方文字稿片段并完成对齐；
6. 页面显示分段预览、待确认片段和说话人列表；
7. 用户可以修正片段归属、修改匿名标签名称，然后选择“保存为当前稿”；
8. 保存接口在服务端重新计算对齐结果，保存 `transcript.json` 的说话人字段，并生成按说话人轮次分段的 `current.md`。

原始 `original.md` 永远不改。用户取消、刷新或任务失败都不写入任何新结果。

首版限制：单个音频最长 30 分钟，文件最大 500MB。超限只提示，不启动模型。这个限制针对当前 Windows 电脑以 CPU 为主的验证阶段，后续根据真实耗时和内存再调整。

## 4. 本地服务接口

新增 `local-audio-service/`，与 Next/Vinext 应用分开安装和启动。服务只绑定回环地址，不暴露到局域网。

### `GET /health`

只返回服务状态、模型状态和 FFmpeg 是否可用。响应不得包含本地绝对路径、token、文件名或音频信息。

### `POST /jobs`

使用 `multipart/form-data` 接收一个音频文件和可选 `expectedSpeakers`（`auto` 或 1–8 的整数）。服务端再次校验扩展名、文件大小和时长，不能只相信浏览器校验；浏览器提供的 MIME 不作为信任依据。

响应：

```json
{"jobId":"随机 ID","status":"queued"}
```

### `GET /jobs/{jobId}`

返回有限状态集合：`queued`、`decoding`、`diarizing`、`ready`、`failed`、`cancelled`，以及百分比、错误类别和完成后的区间：

```json
{
  "jobId": "…",
  "status": "ready",
  "progress": 100,
  "segments": [
    {"startMs": 1200, "endMs": 8400, "speakerId": "speaker_0"}
  ]
}
```

### `DELETE /jobs/{jobId}`

取消排队或运行中的任务。正在执行的 pyannote 调用无法安全中断时，其结果不会发布；任务结束后按自动清理周期删除临时音频和中间文件。服务重启时清理遗留临时目录。

实现初期可以使用 FastAPI + Uvicorn；模型引擎通过 `DiarizationEngine` 接口隔离，测试使用假的 engine，不下载模型。

## 5. 音频与文字稿对齐

官方 `transcript.json` 片段已有 `startMs`、可选 `endMs`、`text`。如果 `endMs` 缺失，使用下一个片段的 `startMs`，最后一个片段使用单集时长或其开始时间加一个保守上限。

对每个文字稿片段，计算它与每个 diarization 区间的时间重叠毫秒数，并选择重叠最多的匿名说话人。输出规则：

- 最大重叠占片段时长至少 60%：自动接受；
- 低于 60% 或没有重叠：标记 `needsReview: true`，仍显示但不伪装为确定结果；
- 说话人区间重叠或片段跨越多人时：保留最高得分，同时将片段标为待确认；
- 所有时间必须是非负整数，区间必须满足 `endMs >= startMs`，顺序异常直接失败回滚。

本地服务不返回或伪造模型置信度。应用对齐后的结果写回 `TranscriptSegment` 的 `speakerId`、`speakerConfidence` 和 `speakerNeedsReview`；`speakerConfidence` 是时间重叠覆盖率，不冒充模型概率。

## 6. Markdown 输出

当前稿不再使用意群整理格式，只按连续的说话人轮次生成段落：

```markdown
### 说话人 1

[00:01:12] 欢迎大家……今天我们主要讨论……

### 说话人 2

[00:02:08] 好的，我先从这个问题开始……

### 说话人 1

[00:03:35] 刚才提到的这一点……
```

- 说话人变化一定开始新段落；
- 同一轮次内的相邻文字直接连接，正文字符顺序保持不变；
- 每个轮次只保留开头代表时间戳，完整片段时间仍保存在 `transcript.json`；
- 未识别或待确认片段使用“待确认”，不生成真实姓名；
- 用户重命名只保存本单集的显示映射，不改变匿名 `speakerId`，便于后续修正。

为避免覆盖用户手工编辑，保存前对当前稿的正文做完整性校验。应用只接受“当前稿仍为官方原稿”或“当前稿由此前本功能生成”两种状态；其他状态返回冲突错误，提示用户先下载后再恢复原稿或自行决定覆盖，默认不写入。浏览器提交的内容只包含时间区间、标签和修正项，服务端始终从已保存的官方片段重建正文。

## 7. 安全、隐私与资源控制

- 浏览器请求本地服务必须带 `X-Speaker-Client-Version: 1`；服务只接受允许的本地来源与回环客户端，拒绝其他 Origin；
- 不在日志中记录音频内容、完整文件名、文稿正文、说话人结果或 Hugging Face token；
- 任务目录使用随机 ID，完成后删除；服务启动时清理超过保留时间的目录；
- Worker 不接收音频字节，也不把音频写入 R2；
- 代码、模型和节目音频的版权/许可分开处理，不能因为代码开源就推定音频可任意使用；
- 本地服务默认 CPU；检测到 2GB 级显存时不强制 CUDA，避免显存不足导致任务失败。

## 8. 测试与验收

前端和 Worker 单元测试不下载真实模型或音频，使用固定的 diarization 区间验证：

- 文字稿片段按重叠最多的说话人正确归类；
- 缺少 `endMs` 时能按下一片段开始时间推算；
- 60% 阈值、跨说话人和无重叠片段正确标记待确认；
- 说话人轮次输出只改变段落和标题，正文逐字符一致；
- 用户重命名和手动修正可 round-trip；
- 非法区间、乱序、错误任务状态不会写入 `current.md` 或 `transcript.json`；
- 超过 30 分钟或 500MB 在浏览器和本地服务两侧都被拒绝；
- 任务取消、超时、服务重启后临时文件被清理。

本机验收顺序：先使用一段 1–3 分钟、两人中文对话音频，确认时间轴和手动修正；再测试 10 分钟音频；最后验证 30 分钟上限和失败回滚。验收通过后再考虑 FunASR/CAM++ 或声纹注册扩展。

## 9. 版本与后续扩展

首版只保存匿名 `speaker_0`、`speaker_1` 等 ID。后续可增加：

- 用户导入短声纹样本，把匿名 ID 映射到跨单集的稳定人物；
- FunASR/CAM++ 作为中文 CPU 后端；
- 可选音频重新转写，但必须作为独立功能并重新确认隐私和许可边界。

本分支不合并此前的意群整理代码；原 `feature/custom-ai-provider` 分支继续保留，用户可随时切回。
