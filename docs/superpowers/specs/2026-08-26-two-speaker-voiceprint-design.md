# 两人声纹模式设计规格

## 背景与目标

当前本地说话人识别使用 pyannote Community-1 做全自动分段和聚类。对于主持人 + 嘉宾这类固定两人播客，全自动聚类会带来较长的处理时间，也可能把同一个人拆成多个匿名说话人。本功能增加一个独立的“两人声纹”模式：用户从同一份音频中各选一段干净的主持人、嘉宾参考片段，系统只在这两个已知类别之间做识别，再将时间区间对齐到已有小宇宙文稿。

本版本的目标是：

- 不改变现有全自动 pyannote 模式；
- 保留本地处理、GPU 自动选择、取消、进度和 2 小时/1GB 限制；
- 让固定两人播客不再执行全自动说话人数聚类；
- 对低置信度、抢话和无法检测到语音的区间保持谨慎，交给现有预览面板人工确认；
- 为将来接入独立参考音频、Silero VAD 或 FunASR CAM++ 留出清晰的引擎接口。

## 非目标

- 本版本不把 ASR 接入声纹模式；没有已有小宇宙文稿时，页面提示先获取文稿；
- 不承诺在多人、严重串音、变声或参考片段含多人时准确区分；
- 不删除、不替换现有全自动模式，也不自动把声纹模式设为默认；
- 不把音频、参考片段或声纹向量上传到远程 Worker、R2 或第三方推理服务。

## 方案与技术选择

### 备选方案

1. 仅在现有 pyannote 流程中固定 `num_speakers=2`。改动最少，但仍执行完整分段和聚类，无法利用已知参考声音，速度收益有限。
2. 参考片段 + 声纹嵌入 + 二分类。本版本采用此方案：先从参考片段建立两个声纹中心，再对正文语音窗口计算嵌入并比较相似度，不做全自动聚类。
3. FunASR CAM++ 一体化转写与说话人识别。适合未来没有文稿的场景，但依赖和部署复杂度更高，暂不作为本版本实现。

### 模型与依赖

- 声纹嵌入：复用 `pyannote.audio` 的 WeSpeaker 预训练嵌入模型（拟使用 `pyannote/wespeaker-voxceleb-resnet34-LM`）。模型按需加载，使用现有 Hugging Face 登录状态。
- 语音检测：封装为独立 VAD 接口。首版使用本地轻量实现，优先跳过静音，不新增 ASR；若基准音频显示边界质量不足，可在同一接口内替换 Silero VAD/CAM++，不改变任务和前端协议。
- 设备：沿用 `SPEAKER_DEVICE=auto|cpu|cuda`。声纹嵌入模型和 VAD 模型在 CUDA 可用且能移入显存时使用 GPU，失败时回退 CPU，并通过健康接口报告实际设备。

实现状态（2026-08-27）：参考区间契约、二分类/平滑、10 分钟分块 `VoiceprintEngine`、JobManager/FastAPI 协议、浏览器播放器和 artifact/Markdown 来源均已接入；模型仍采用按需加载，尚未在本机下载真实 WeSpeaker 权重。速度、显存和准确率待使用真实双人音频基准后再调整。

上述模型/API 依据 pyannote.audio 官方文档和 Hugging Face 模型页；速度、相似度阈值和显存占用必须以本机 5 分钟基准实测为准，不在规格中承诺固定倍速。

## 用户流程与界面

在现有“按说话人分段”窗口中增加模式选择：

1. 用户选择本地音频。页面继续显示 2 小时、1GB 上限，并用浏览器播放器预览文件。
2. 选择“全自动识别”时保持现有流程和说话人数选择。
3. 选择“两人声纹”时显示两组参考时间范围：主持人开始/结束秒数、嘉宾开始/结束秒数。每段必须为 10–30 秒、在音频时长内、互不重叠。
4. 页面提示参考片段应尽量只有一人连续说话，避免片头音乐、多人抢话和明显噪声。校验失败时不创建本地任务。
5. 点击开始后沿用现有轮询、进度、取消和错误提示。完成后进入同一预览面板；声纹模式默认标签为“主持人”和“嘉宾”，仍可改名和逐段修正。
6. 保存前沿用当前稿哈希保护，保存后关闭窗口并刷新当前稿。

参考片段的时间点仅发送到本机服务，不保存到数据库或文稿；浏览器对象 URL 在关闭/重选文件时释放。

## 本地服务接口

### 创建任务

继续使用 `POST /jobs` multipart 请求。旧请求只携带 `audio` 和 `expectedSpeakers`，行为不变；新请求增加：

```text
mode=voiceprint
references={"speaker_0":{"startMs":...,"endMs":...},"speaker_1":{"startMs":...,"endMs":...}}
```

服务端解析并严格校验：模式只能是 `diarization` 或 `voiceprint`；声纹模式必须恰好有两个参考区间；每段 10–30 秒、开始小于结束、落在音频时长内且不重叠。服务端再次执行文件格式、1GB 和 2 小时校验，不能依赖浏览器校验。

任务查询和取消路径不变。任务快照新增 `mode`，区间输出继续为兼容现有网页的：

```json
{"startMs":0,"endMs":1500,"speakerId":"speaker_0"}
```

声纹模式固定 `speaker_0` 为主持人参考、`speaker_1` 为嘉宾参考；未知区间不输出伪造的第三类 ID，而是留下时间空洞，令文稿对齐结果进入“待确认”。

健康接口保留现有 `model`/`device` 字段，并增加声纹模型的可选状态字段。旧客户端只读取旧字段也必须继续工作。错误码至少包括：`VOICEPRINT_REFERENCES_INVALID`、`VOICEPRINT_MODEL_UNAVAILABLE`、`VOICEPRINT_LOW_CONFIDENCE`、现有音频和任务错误码。

## 处理链路

`VoiceprintEngine` 与 `PyannoteCommunityEngine` 实现相同的任务回调协议，但内部独立：

1. 任务启动后按现有 10 分钟核心窗口 + 15 秒重叠读取 16kHz 单声道音频；不把整段 2 小时音频一次性放入内存。
2. 对每个参考区间执行 VAD，切成约 1.5 秒、带重叠的有效语音窗口；有效语音不足时任务失败并提示重新选择干净片段。
3. 批量提取两个参考集合的嵌入，分别做 L2 归一化和平均，形成主持人/嘉宾中心向量。
4. 对正文只处理 VAD 找到的语音窗口，批量提取嵌入，计算与两个中心向量的余弦相似度。
5. 同时满足绝对相似度和两类相似度差值的窗口才标记说话人；其余窗口视为未知。通过相邻窗口多数平滑、最短持续时间和相邻同类合并生成不重叠的时间区间。
6. 裁剪每个分块到核心窗口，避免重叠区重复输出；由于类别来自全局参考向量，不需要现有的跨块匿名 ID 映射。
7. 进度回调保持 0–100 语义：上传/解码/模型准备阶段与分块处理阶段可见，前端继续显示当前块数。

阈值、窗口大小、批大小和最短持续时间集中在声纹引擎常量中，并通过单元测试覆盖；不把未经基准验证的数值暴露为用户可调参数。参考片段含多人、背景音乐或两类声音相似时，低置信度策略优先于强行归类。

## 文稿对齐与持久化

- 复用 `alignTranscriptSpeakers`、预览和人工 overrides；对齐输入格式不变。
- 预览/保存请求增加受限的引擎标识和可选标签。声纹模式默认传递两个已知标签，后端仍只接受实际出现的 speaker ID。
- `SpeakerLayout.engine` 扩展为 `pyannote-community-1` 和 `pyannote-wespeaker-voiceprint-v1`，旧 artifact 继续可解析。
- Markdown frontmatter 的 `speaker_source` 在全自动模式保持原值，声纹模式写入 `pyannote-wespeaker-voiceprint-v1`。
- 保存前继续比较当前稿哈希；如果用户已经手动修改当前稿，返回冲突而不是覆盖。

## 错误处理与隐私

- 浏览器校验失败：不发送文件、不创建任务，说明具体字段。
- 本地服务无法连接、模型未登录/未下载、CUDA 初始化失败、音频解析失败：沿用现有错误翻译，并区分“可重试配置问题”和“本次任务失败”。
- 低置信度区间不被当作确定说话人；预览显示待确认，用户可以改归属或保留待确认。
- 本地服务仅监听回环地址，继续要求允许的 Origin、客户端版本头和无站点 Cookie；任务清理策略删除上传文件及临时目录，服务不记录音频正文、参考内容或声纹向量。

## 测试与验收

### 自动测试

- Python：参考区间解析/边界校验、声纹引擎参考向量与二分类、低置信度留空、平滑合并、分块裁剪、任务分派、健康状态和错误码。
- TypeScript：声纹模式 multipart 字段、任务快照解析、模式/标签传入预览与保存、前端模式切换和参考范围校验；现有全自动客户端测试必须继续通过。
- 回归：现有 JavaScript、Python 单元测试和构建/lint 全部执行。

### 手工基准

- 使用已有 5 分钟双人音频，分别选取干净主持人和嘉宾参考片段；记录 CPU/GPU、总耗时、显存、输出区间数量和人工修正数量。
- 与现有全自动模式对比速度和错分情况。只有在实际结果可接受后，才考虑调整默认阈值或 VAD 实现；若效果不足，保留模式但明确提示用户改用全自动或人工复核。
