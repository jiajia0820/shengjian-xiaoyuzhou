# 下线学习 Prompt 生成功能设计

## 状态

已获用户确认，待实施。

## 背景

当前应用同时支持“内容梳理”和“学习 Prompt”两类 AI 分析。用户决定停止学习 Prompt 的新生成，但希望保留历史上已经生成的结果，以便继续查看、复制和下载。本次改动只下线学习 Prompt 的生产路径，不删除历史分析记录、对象存储文件或数据库类型。

## 目标

1. 新的用户操作和 API 请求不能再生成学习 Prompt。
2. 已有 `learning_prompt` 分析结果继续可读、可复制、可下载。
3. 不改变内容梳理、声纹识别、AI 整理和自定义 AI 提供商功能。
4. 不扣除额度、不创建 lease，也不调用模型来处理被下线的生成请求。
5. 页面文案、README 和测试不再把学习 Prompt 描述为可用的新功能。

## 非目标

- 不批量删除或改写已经保存的学习 Prompt Markdown。
- 不删除 `analysis_results` 中的 `learning_prompt` 行，也不新增数据库迁移。
- 不改变历史结果的 frontmatter、来源哈希、模型元数据或下载文件名。
- 不把学习 Prompt 的内容迁移为内容梳理。

## 方案比较与决策

### 方案一：下线生成、保留历史只读入口（采用）

只保留历史结果的读取路径；当单集存在历史 `learning_prompt` 结果时，页面显示“历史 Prompt”标签，提供查看、复制和下载，不显示来源选择或重新生成按钮。生成接口对 `learning_prompt` 返回 410，并在扣额度、取得 lease、读取 AI 配置前结束请求。数据库和 GET/下载接口继续兼容旧记录。

优点是满足保留历史资料的要求，行为边界清晰，改动集中且可以随时从 Git 历史恢复；缺点是需要在页面区分“历史 Prompt”和可生成的内容梳理。

### 方案二：保留原标签并显示功能下线提示

保留“学习 Prompt”标签，但禁用生成按钮并显示说明。实现量较小，但废弃功能仍然占据主界面，用户容易误以为可以重新生成，因此不采用。

### 方案三：删除数据库类型和历史对象

删除 `learning_prompt` 记录及其存储文件并清理数据库字段。该方案会破坏历史资料，与用户确认的保留历史结果要求冲突，因此不采用。

## 详细设计

### 1. 前端页面

- `AnalysisResult.kind` 和 `DocumentTab` 继续包含 `learning_prompt`，用于读取旧结果。
- 打开单集后，只有在分析结果列表中发现 `kind === "learning_prompt"` 时才显示“历史 Prompt”标签；没有历史结果的新单集完全不显示该标签。
- “历史 Prompt”页面仅显示历史结果的来源、生成时间、复制和下载操作；隐藏框架选择、分析来源选择、开始生成和重新生成按钮。
- 历史结果读取失败时沿用现有分析读取错误提示，不提供新的生成入口。
- 删除单集的确认文案不再把学习 Prompt 当作可生成能力，但可以说明历史分析结果会随单集一起删除。
- AI 设置、首次连接提示和其它页面文案只保留“内容梳理”的新生成说明。

### 2. 生成 API 与服务端

- `POST /api/episodes/:eid/analyses/generate` 的 `kind` 解析只接受 `summary`。
- 客户端或第三方直接发送 `kind: "learning_prompt"` 时，返回 HTTP 410，错误码为 `ANALYSIS_KIND_REMOVED`，消息为“学习 Prompt 生成功能已下线，历史结果仍可查看”。
- 该拒绝发生在读取文稿、同步原稿哈希、扣除 AI 额度、取得分析 lease 和读取 AI 配置之前，确保没有外部模型调用或状态变化。
- `GET /api/episodes/:eid/analyses`、带 `slot` 的读取接口和下载接口保持原有行为，继续按所有权校验读取历史 `learning_prompt` 记录。
- `buildAnalysisMarkdown` 保留历史 `learning_prompt` 标题分支，避免旧结果格式和类型在读取、下载时被破坏；新生成路径只会传入 `summary`。

### 3. 分析模块与文档

- 从 `generateAnalysisBody` 中删除学习 Prompt 的新生成提示词、分支和专用调用逻辑，只保留内容梳理生成。
- `AnalysisKind` 保留联合类型，作为历史记录和读路径的兼容类型；必要时使用仅含 `summary` 的生成类型约束新调用。
- 删除仓库根目录中过时的 `Prompt.md` 生成规范，避免它继续被误认为当前可用功能；Git 历史仍可找回该文件。
- 更新 README、布局描述和设计/计划说明中把学习 Prompt 作为当前功能的表述，明确历史结果兼容范围。

### 4. 数据流

```text
打开单集
  ├─ 读取文稿
  └─ 读取全部分析结果
       ├─ 只有 summary ──> 页面显示“文稿 / 内容梳理”
       └─ 含旧 learning_prompt ──> 额外显示“历史 Prompt”（只读）

新生成请求
  ├─ kind=summary ──> 原有内容梳理流程
  └─ kind=learning_prompt ──> 410 ANALYSIS_KIND_REMOVED（不扣额度、不占 lease）
```

历史分析记录仍由现有单集删除和账户删除流程统一清理；本次不改变这些删除行为。

### 5. 错误处理与兼容

- 旧客户端仍发送学习 Prompt 生成请求时，收到稳定的 410 和中文提示，而不是通用 400 或服务器错误。
- 页面只读入口不依赖 AI 配置；即使用户后来删除 AI 配置，也能查看和下载历史结果。
- 历史 Prompt 的 `source_hash` 变化仍按现有规则显示“分析已过期”，但不出现重新生成按钮。
- 不新增数据迁移；旧数据库、运行时临时表和对象存储键继续有效。

## 测试与验收

### 单元与路由测试

- 生成路由对 `kind: "learning_prompt"` 返回 410，且 `consumeUsage`、`acquireAnalysisLease`、模型执行器、写对象和写数据库均未调用。
- 生成路由对 `kind: "summary"` 的现有成功、错误、敏感输出和额度逻辑继续通过。
- `GET` 和下载历史 `learning_prompt` 的测试确认记录和 Markdown 仍可返回。
- 分析类型和 Markdown 标题兼容测试确认旧结果仍识别为学习 Prompt。

### 渲染与静态测试

- 无历史 Prompt 时渲染结果不含“学习 Prompt”生成标签、按钮和生成说明。
- 有历史 Prompt 时只渲染“历史 Prompt”只读标签、复制和下载操作，不渲染重新生成按钮。
- 内容梳理标签、框架选择、生成按钮和原有文稿工具栏保持可用。
- README、布局描述和设置提示不再声称可以生成新的学习 Prompt。

## 回滚方案

本次实现使用独立提交；如需恢复学习 Prompt 生成，只需回滚该提交即可。历史记录和 `Prompt.md` 均可从回滚前的 Git 提交恢复，不需要数据库回滚。
